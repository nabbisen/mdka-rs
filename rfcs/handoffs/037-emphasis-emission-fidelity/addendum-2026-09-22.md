## 1. Criterion 2 is relaxed: order is not always expressible

The handoff's §3 said order preservation was reachable and offered an escalation if it turned out not to be.
It is reachable **only when the span is surrounded by whitespace or punctuation**. Intraword it is not
expressible at all — I tested every encoding:

```
a***x***b   -> em(strong("x"))          the other order; the only thing that parses
a**_x_**b   -> "*","*", em("x"), "*","*"
a__*x*__b   -> "_","_", em("x"), "_","_"
a*__x__*b   -> "*", strong("x"), "*"
```

CommonMark flanking: `**` preceded by an alphanumeric and followed by `_` (punctuation) is not
left-flanking, so it cannot open. **Criterion 2 now reads: preserve order where the delimiters can flank.**

You reported no escalation was needed, and against the shapes you tried that was true. The gap was that
neither the cells nor any battery fixture puts an emphasis span inside a word — every `strong><em` fixture
in all fifteen directories is the isolated form. Not something the package should have caught by process;
recording why it was invisible.

## 2. 🛑 Required: the swap must be conditional, and it currently regresses

As it stands the swap fires unconditionally, and intraword it **loses the bold entirely**:

```
<p>a<strong><em>x</em></strong>b</p>
  21950bc : a***x***b  ->  para("a", em(strong("x")), "b")     order wrong, both emphases present
  yours   : a**_x_**b  ->  para("a","*","*", em("x"), "*","*","b")   bold gone, literal ** in the prose
```

Also `foo…baz`, `…tail`, and `lead…` — four shapes in the review's §1 table.

**That is worse than the defect it fixes**: it drops an emphasis level *and* puts literal asterisks in the
text, which is §5.3 — the other half of this RFC — reappearing somewhere new.

**The invariant to implement:**

> **Never lose an emphasis level to gain ordering.** Preserve both emphases always; preserve their order
> only where the delimiters can flank.

Concretely: swap to `_` only when the characters before the opening run and after the closing run are absent
or non-alphanumeric. Otherwise emit `***x***` — order lost, both emphases intact, **byte-identical to
`21950bc`**.

**Criteria for the change:** the four intraword shapes byte-identical to `21950bc`; the isolated shapes keep
`**_x_**`; cells for both groups in all five modes; re-check
`tests/inline_around_blocks.rs`'s assertion, which may need to stay `***x***` for the intraword case while
the isolated case becomes `**_x_**`.

## 3. Everything else stands

The empty-emphasis half is complete — all eight rows verified by parse, including `<p><b></b></p>` emitting
nothing at all. Same-class collapse is right, including the three-level shape the RFC put out of scope. All
five criterion-5 controls are byte-identical.

**Two calls worth keeping as precedent:** undo-on-empty instead of a capture, because a capture would have
changed the preceding-byte context escaping reads — the reasoning is right and should be reused; and folding
`flush_space` into the mark so a removed span restores the space to *pending* rather than keeping or dropping
it, with `last_was_space` deliberately not restored. Both are the subtle correct answers.
