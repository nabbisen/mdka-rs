## 1. The container claim is too broad

It currently says a declaration *"reaches every descendant block, the same way a browser would
render it."* Measured:

| | |
|---|---|
| `<div style=…><p>` , `<h2>` , `<blockquote><p>` , `<li><p>` | ✅ emphasised |
| `<blockquote>` bare text, `<li>` bare text | ❌ not |
| `<td>` — **even with `<p>` inside** | ❌ not |

Replace the sentence with what is true: **paragraphs and headings, including a paragraph nested
inside a quote or list item; not table cells, and not the bare text of a list item or blockquote.**
Say plainly that whether a list item is emphasised depends on whether its text is wrapped in `<p>`.

**Do not widen the code to cover these.** The decided cases are met, the option is off by default,
and output with it off is byte-identical to `3.0.0`. Documenting the boundary is the whole task.

## 2. The Minimal gap belongs in the docs, not only in a test name

Your finding is correct and the reasoning is sound. But the consequence is that **the option does
nothing for its own motivating case in `Minimal`**:

```
Google Docs shape, Minimal  → "bold plain"
Google Docs shape, Balanced → "**bold** plain"
```

Document it in `options.md` with that example, and say it follows from `Minimal`'s wrapper unwrapping
rather than from a limit of the option.

## 3. A cross-reference that goes nowhere

`options.md` says *"See Conversion Modes for what this means when choosing a mode."* `modes.md` does
not mention this option. Add it there, or drop the line.
