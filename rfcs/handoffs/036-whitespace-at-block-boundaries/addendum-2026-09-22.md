## 1. Baseline test count — the handoff's "405" is wrong; it is **407**

`implementation-handoff.md` states a baseline of 405 passing tests at `bec40bf`. That number is mine and it
is an error: I ran plain `cargo test`, which runs fewer binaries than
`cargo test --workspace --all-features`. Re-measured in a clean worktree of `bec40bf`: **23 binaries, 407
passed.**

The implementer caught this, reconciled it across three commits, and flagged it rather than building on it.
Acceptance criterion 5 ("more than 405") should be read as **more than 407**; it was met either way (424).

## 2. §1's "none of the four is a `2.3.0` regression" is wrong for slice 4

The handoff says all four defects reproduce identically in `2.2.3`. That is true for slices 1, 2 and 3, which
I measured. **It is false for slice 4**, which I did not measure — and it is the one that broke.

| Shape | `2.2.3` | `2.3.0` (`bec40bf`) |
|---|---|---|
| `empty_li_d3` | `- \n  - \n    -` → `ul(li(ul(li(ul(li())))))` — correct | `- - -` → **`hr`** |
| `empty_li_d5` | correct, five levels | **`hr`** |
| empty item with a non-empty sibling | correct | `hr` + indented code block — **content destroyed** |

RFC 035's `only_markers` single-line idiom introduced it: three or more unordered markers sharing a line
satisfy CommonMark's thematic-break grammar, and thematic break wins the tie.

**This raises slice 4's value, not its difficulty** — the work as delivered is the fix. It is recorded here
because a handoff that misstates whether something is a regression misprices it for whoever reads it next.

## 3. §6's sink caution was scoped too tightly

The handoff says *"the sink is not the bug… if you find yourself changing the sink, explain why before you
do."* That was aimed at RFC 035's continuation-prefix logic, which is indeed correct and was not the bug. It
was not a ban on the file.

Slice 4's sink change was justified properly and is accepted. Slice `036b` requires a further one: the
leading-strip clear belongs at the sink's single write choke point. Read §6 as *"explain why"*, which is what
was done, not as *"avoid"*.
