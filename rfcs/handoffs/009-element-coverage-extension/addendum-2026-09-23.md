## 1. 🛑 `~~` needs RFC 037's collapse rule

```
<p><del><del>x</del></del></p>   ->  ~~~~x~~~~  ->  code()      "x" IS GONE
<p><del><s>x</s></del></p>       ->  ~~~~x~~~~  ->  code()      same, mixed tags
```

`~~~~` at the start of a line is a **tilde code fence**, so the content is destroyed — under both readings.
Mid-line it only degrades (`a~~~~x~~~~b` stays literal), which is why it is easy to miss.

And the milder sibling:

```
<p><del>a</del><del>b</del></p>  ->  ~~a~~~~b~~  ->  Strikethrough("a~~~~b")
```

**This is RFC 037 §3** — *"collapse nested emphasis of the same delimiter class to one level"* — and `~~` is
a delimiter class. RFC 037 also settled that the rule is about the **delimiter, not the tag**, which
`<del><s>` confirms. Building `~~` separately from `emphasis_open` was the right call for the reasons you
gave; the collapse rule simply did not come with it.

**Where RFC 037's answer does not transfer.** It handled the *adjacent* case by alternating `**`/`__`.
**There is no alternation for `~~`** — I checked: `~single~` does parse as strikethrough, but `~~a~~~b~`
does not, because both forms use the same character and the runs still meet.

**For adjacent spans I recommend merging** — `<del>a</del><del>b</del>` → `~~ab~~`. It renders identically to
the source and loses only the boundary between two spans that were visually one; the alternative is literal
`~~~~` on the page. **If you find something cleaner, take it and say what it was.** An HTML comment separator
works and injects HTML, which RFC 008 §4 and RFC 009 §4.3 both declined.

**Criteria:** the four shapes above; a single `<del>`/`<s>` unchanged; `<del>` around block content unchanged
(RFC 028 still drops the delimiters — verified working today); cells for each, all five modes; non-affected
output still byte-identical to `7e7cec2`.

## 2. Everything else is approved

`<dl>` cannot weld — I tried `<dt>`-only, an orphan `<dd>` and an empty `<dt>`. Task markers fire exactly
when they should and not for a `radio` input or a non-first checkbox. `<sup>`/`<sub>` map `2⁷`, `H₂O`, `xⁿ`,
`⁻¹`, `⁽²⁾`, leave `7a` and `N` alone, are guarded inside code, and the citation marker is **byte-identical**
to `7e7cec2`. All four work inside a table cell without regressing the table. **420 comparisons against
`7e7cec2`: zero differences.**

**Two decisions worth keeping as precedent:** capturing the `<sup>` subtree's *own rendering* rather than its
source text, which is why the 99% citation case is provably untouched instead of probably untouched; and
keeping the checkbox lookahead out of `structure_hints` because it aggregates nothing from below — resisting
that pull is what keeps a pre-pass meaning one thing.
