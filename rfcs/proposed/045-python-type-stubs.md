# RFC 045 — `py.typed` without stubs makes a type checker certify wrong code

**Status.** Proposed
**Author.** Architect
**Created.** 2026-09-25
**Milestone.** Unassigned. Packaging and typing only; no conversion change.
**Source.** The `2.4.0` consumer pass; owner accepted option A — ship stubs — on 2026-09-24, together with the mechanism in §4 that the original recommendation lacked.
**Touches.** `python/mdka/` (new `.pyi`), `python/pyproject.toml` or the maturin manifest if stubs need listing, `.github/workflows/ci.yaml`, `docs/src/getting-started/usage-python.md`.
**Relates to.** RFC 039 A6, which asked for the marker and whose criterion this corrects.

---

## 1. The defect

The published `2.5.1` wheel contains `mdka/py.typed` (0 bytes) and **zero `.pyi` files**. The marker tells a
type checker the package is typed; nothing then describes any type, so every symbol resolves to `Any`.

Measured against the published wheel:

```
$ cat typecheck.py
import mdka
n: int = mdka.html_to_markdown("<p>x</p>")   # str assigned to int
mdka.html_to_markdown(12345)                 # int passed as html
mdka.html_to_markdown()                      # required argument missing

$ mypy --strict typecheck.py
Success: no issues found in 1 source file
```

**Without the marker, mypy reports *"missing library stubs or py.typed marker"* — true, and useful. With it,
the user gets a false clearance.** We did not merely fail to help; we replaced a correct warning with an
incorrect all-clear, which is the worst of the three options.

**RFC 039 A6's criterion was *"mypy no longer reports the package as untyped"*.** The implementation
satisfied it exactly. The criterion was the wrong shape — it described a symptom disappearing rather than a
promise being kept.

## 2. The surface is small

Fourteen public names, of which thirteen are documented. From the published wheel:

| Kind | Names |
|---|---|
| Functions, no options | `html_to_markdown(html)`, `html_to_markdown_many(html_list)`, `version()` |
| Functions, with options | `html_to_markdown_with`, `html_to_markdown_many_with`, `html_file_to_markdown`, `html_file_to_markdown_with`, `html_files_to_markdown`, `html_files_to_markdown_with` |
| Types | `ConversionMode` (`Balanced`, `Strict`, `Minimal`, `Semantic`, `Preserve`), `ConvertResult` (`src`, `dest`), `BulkConvertResult` (`src`, `dest`, `error`, `ok`), `MdkaError(Exception)` |
| Not documented | `mdka_python`, the compiled submodule — see §5 |

PyO3 emits text signatures, so `inspect.signature` already returns the real shape, e.g.

```
html_to_markdown_with(html, mode=..., preserve_ids=None, preserve_classes=None,
                      preserve_data_attrs=None, preserve_aria_attrs=None,
                      drop_interactive_shell=None, unwrap_unknown_wrappers=None)
```

**The stubs must match the runtime, not the ideal.** Three of those keywords — `preserve_classes`,
`preserve_data_attrs`, `preserve_aria_attrs` — are deprecated and inert but **accepted**, and must appear.
`preserve_unknown_attrs` is **rejected** at runtime with `TypeError` and must not.

## 3. Proposal

Ship `.pyi` stubs for the thirteen documented names, matching the runtime surface exactly.

## 4. The part that makes it durable

My original recommendation priced this as *"real work, and a second surface to keep in sync"*. **That cost is
avoidable, and leaving it unaddressed would repeat the mistake this project keeps finding: a promise with
nothing asserting it.**

**`stubtest` — mypy's own tool — compares a stub against the live runtime module** and reports anything
missing, extra, or differently shaped. Run in CI, the second surface stops being a thing that drifts and
becomes a checked invariant.

This is the same move as `2.4.2`'s inertness properties and RFC 042's artifact contract, and it is the
condition on which the owner accepted option A.

**`stubtest` imports the compiled module, so CI must build the extension before running it** — the Python job
already does this for pytest.

## 5. Also in scope, because it is the same file

`mdka_python`, the compiled submodule, is exported into the public namespace: `dir(mdka)` gives 14 names
where 13 are documented. It was found in the documentation audit and recorded against RFC 041's structural
work. **Whatever the stub does about it decides what a type checker thinks the surface is**, so it cannot be
deferred past this RFC: either exclude it from `__all__` and the stub, or document it. Excluding it is the
obvious choice; the RFC does not pre-empt the implementer's reading of why it is exported at all.

## 6. Not in scope

- Any conversion behaviour, option, or binding signature. **Nothing here changes what mdka does.**
- Node.js typings: `index.d.ts` is generated by napi and already checked by the `ts` block in the docs gate.
- Removing `py.typed`. That was the fallback if stubs were not worth doing; they are.

## 7. Acceptance criteria

1. **The three lines in §1 all fail under `mypy --strict`**, with the right messages. Demonstrated before and
   after, as `2.4.2` and RFC 043 were.
2. `stubtest` passes against the built extension, and **runs in CI** — not only locally.
3. **`stubtest` is shown catching a deliberate mistake**: remove a keyword from a stub, watch it fail, restore
   it. A checker that has only ever passed has not been shown to work.
4. Every one of the thirteen documented names is present with its real shape, including the three deprecated
   keywords and excluding `preserve_unknown_attrs`.
5. The published wheel **contains** the `.pyi` files — verified by building the wheel and listing it, not by
   trusting the manifest. `py.typed` stays.
6. `docs/src/getting-started/usage-python.md` no longer says stubs are missing; its hand-written signature
   list becomes redundant and should go or point at the stubs.
7. Python tests still pass; no change to any other binding.

## 8. A note on sequencing

The false all-clear is **live now**. The owner asked whether to remove the marker in the interim and I said
the better answer was not to have an interim. **If this slice is going to wait, that question comes back**,
and removing the marker is the honest position while it waits.
